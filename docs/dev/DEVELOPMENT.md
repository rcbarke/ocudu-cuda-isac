# Implementing receiver-aware ISAC on CUDA-OCUDU

**First hardware result (accepted).** One DGX Spark builds the pinned WG1 receiver and reproduces the correctness comparison in the 20 MHz, one-layer row of DeepSig Table II. **Demonstration (next).** One UE, one layer, four RX, 20 MHz/51 PRBs at 30 kHz SCS on the same Spark. No UE or core is attached: a Sionna RT radar CFR applied at the receiver stands in for a UE transmitting through a moving-target scene. The receiver decodes the known uplink and exports its own CUDA channel estimate. A second MPS client runs a cuSense-like pipeline on that estimate and publishes a causal presence decision, a delay–Doppler view and a location map. A lightweight browser page shows the radio, sensing and system KPIs live. Deadlines and service levels are calibrated on the implementation before anything is graded against them. **Collocated study.** Bring every radar, AI, channel-source, split and memory ablation up on that one Spark under MPS. Then attach a software UE on the split-8 ZeroMQ boundary. **Systems study.** Repeat the frozen workload across two Sparks on a 100 Gb/s CX7 link and across MIG instances on a GB300. **Capstone.** Run the same sensing core on Aerial Framework. Then swap DeepSig-OCUDU for Aerial-OCUDU with the same contribution code, evaluate over the air and compare with cuSense. **Publication.** Measure how receiver processing, model choice, load and placement affect timely sensing at a fixed false-alarm operating point while preserving a specified radio service level.

|---|---|---|
| D1 · Decode through the replayed channel | S2.1–S2.4, S4.4, S4.5 | CRC, payload match and CPU/GPU service time for a known transport block sent through the moving-target channel |
| D2 · Observation and radar view | S3.1–S3.4 | The observer's pilot LS (O2) leaving the receiver, the delay–Doppler map and a presence score that moves with the target |

| D4 · cuSense-like sensing under MPS | S3.5, S4.1, S4.6, S4.2, S4.3 | Location map and presence computed from O3 in a second MPS client, calibrated deadlines, DSP-only against concurrent, the scorecard |

The live showing needs D4. S4.3's archived evidence run (three paired repetitions on 20 held-out episodes) can follow the showing and closes the ticket. Every Unit gate applies in full.

**The receiver's estimate is in the demonstration.** S5.2 keeps its number and is built here, on the staged harness. The pinned kernel already holds the estimate on the device after pilot LS, frequency interpolation and smoothing, per DMRS symbol, and the pin declares a diagnostic accessor for that buffer. That is the stage cuSense reads from Aerial. The work is a read-only route from the GPU demodulator to the observer, an ordered copy and the parity check. The patched receiver is built from a separate worktree into its own build directory, so the submodule stays pristine and the accepted S1.1 build is the hook-free control. O2 stays as the parity reference and as the fallback input.

**No UE is attached.** The demonstration has no UE, no 5GC and no PRACH procedure. A Sionna RT radar CFR applied to a legal grant at the receiver stands in for a connected UE transmitting through the scene. S6.10 later checks that shortcut against a software UE, and M5 against commercial UEs.

**Comparable, not replicated.** The demonstration measures this simulation. Position error and latency are recorded beside cuSense's published figures and are not graded, exactly as S1.2 recorded Table II timing beside the paper's. The published position error belongs to one room and one over-the-air system and is not a target.

**Deadlines are calibrated, not assumed.** The 5 ms and 50 ms sensing deadlines and the radio allowance are starting proposals. S4.6 measures the implementation, derives them by rules fixed in advance and verifies them on a second run before any held-out episode is read. S1.2 timing was accepted with host tuning deferred, so the demonstration's values hold for the recorded host state. S5.6 tunes the host and recalibrates for the paper, and every later placement repeats the calibration as its first Integrate step.

Three rules keep the axes independent.

1. **The sensing core has no host.** `src/ocudu_cuda_isac/sensing/` imports no OCUDU binding, no Sionna package and no adapter. It consumes the observation record and returns decision records. An import test enforces this from S3.3 on.
2. **Each host is an adapter.** `native/ocudu_adapter/` serves DeepSig-OCUDU at every split. `adapters/aerial_framework/` (S10) and `adapters/aerial_ocudu/` (S11) emit the same observation record and accept the same decision record.
3. **Simulation stays offline.** Sionna and Sionna RT are used in `src/ocudu_cuda_isac/episodes/` and in training. No slot loop calls them.

## How to implement and sign off one ticket

1. Select the card, its production owner and fixtures. Open one patch against the named package or native target. Resolve the exact upstream symbol and commit first. Reuse OCUDU's grants, PUSCH and CRC, Sionna's NR generator/ISAC primitives, RT's solvers, library FFT/eigensolvers and PyTorch layers. Commit small fixtures or their creation recipe with an independent expected answer.
2. Implement the production interface and run its focused unit test inside this checkout's `isac`. Inject a test clock, fake grid/transport or small tensor as specified. A component can be **unit accepted** before any hardware integration. Upstream whole-project integration suites are separate from building an individual adapter.
3. When the integration prerequisites exist, run the real producer and consumer. Grade against the named observable. Archive a unique run ID, command, inputs, toolchain/commit/patch hashes, raw logs, counts, judgment and reason. Preserve failed attempts. Record a blocked host or missing optional system explicitly. A skip, zero executed cases, a dry run or a fallback cannot close the requested hardware gate.
4. Mark the sprint **integrated** only with its real evidence. Keep unit and integration status separately in the issue/PR. For studies, a correctly measured adverse result completes the experiment. Passing a functional gate never implies a published speedup or service level.

**Command contract for future tickets.** The S2–S9 card heading gives a selector. Each implementing patch provides a directly executable `tests/unit/test_<selector>.py` with a `unittest.main()` entry point and a matching `tests/integration/<selector>.py` plus `configs/integration/<selector>.json`. Create the specific files with the feature. The native adapter may use a small CMake/CTest target with a fake interface and a thin Python test wrapper. Production C++ should build against the locked headers, and CPU-only unit targets should link only their module and doubles. Each integration driver takes `--config FILE --output-dir DIR`, refuses to overwrite an existing run, and writes a grade with an explicit case count. The two commands below exercise S3.1 after implementation.

```sh
python tests/unit/test_pilot_ls.py -v
python tests/integration/pilot_ls.py --config configs/integration/pilot_ls.json \
    --output-dir results/runs/s31-spark-001
```

These are build contracts for future patches. Runnable commands in S0/S1 are identified below. Keep hardware drivers outside default unit discovery and make each hardware command opt-in. Use `tests/unit/__init__.py` for discovery when adding the first future unit module. Never count an absence of imported tests as a successful gate. From S3.3 on, `tests/unit/test_core_imports.py` asserts that `ocudu_cuda_isac.sensing` imports no host adapter, OCUDU binding or Sionna package. [Evidence format](REPRODUCE.md)

## Interfaces shared across tickets

The [replay contract](../interfaces/REPLAY.md) defines the shipped `fixture-grid/v1` vectors. The following fields belong to the production interfaces introduced by S2–S5. Keep the fixture readable for regression and add a schema version for the production records.

| Crossing | Required record and invariant |
|---|---|
| S2.1/S2.2 → S2.3 | Keep the grant, original TB, X/H/W arrays, axis/units metadata and checksums in the stimulus store. Bind one realization to its grant. Map frequency by physical offset and time by actual symbol timestamp. S2.1 delivers the grant, the TB and X as a `pusch-grant-store/v1` entry in carrier coordinates. [Grant record](../interfaces/GRANT.md) |
| S2.3 → S2.4 | Pass an owned or retained Y grid, its generation, PDU and ready event. The decoder sees the matching legal PUSCH allocation. Save the readback digest and true decoder callback independently of observer state. |
| S3.1 or S5.2 → S3.2 | Define a versioned descriptor with run/epoch, opaque episode and grant/opportunity IDs, cell/UE, absolute slot, source stage (O2/O3), shape, dtype, strides, mask, antenna map, time unit/domain and completion handle. Use opaque IDs only for joins. |
| S3.2 → S3.3/S3.4 | Transfer immutable observations and release credits by generation. A decision identifies all contributing observations, clock domain, first/last sample, publication time, frozen model/threshold and validity status. |
| S4–S9 → offline evaluation | Use `radio.jsonl` for true CRC, byte counts and terminal radio outcomes, `events.jsonl` for releases/copies/drops and `decisions.jsonl` for publications. Join to evaluator-only labels and original TBs after the run. Missing outcomes remain in their original denominators. |
| Any reference signal → observer (S2.1, S6.9) | A sensing-source record (`sensing-source/v1`) names the channel, link direction, RE mask, reference symbols, ports, executing processor and slot timing. S3.1 computes LS for any registered source. `pusch_dmrs` is the first entry, registered in `src/ocudu_cuda_isac/sensing/sources/`. |
| Observation → sensing core (S3.3 on) | A radar cube indexed `[frequency, slow time, RX]` with axes in Hz, seconds and element positions, a validity mask, the source ID, the receiver stage and the UE realization. The core imports nothing host-specific. |
| Run records → KPI stream → page (S4.4, S4.5) | `kpi/v1` records in `kpi.jsonl`: derived, windowed and read-only. Nothing is graded from them, and their counts must equal the S4.2 reduction. [KPI contract](../interfaces/KPI.md) |
| Host adapter ↔ core (S5.4, S10, S11) | DeepSig-OCUDU at any split, Aerial Framework and Aerial-OCUDU each emit the S3.2 descriptor and accept `decisions.jsonl` records. Host-specific fields live under one `host` key. |

For a minimal fake producer, use one epoch, one UE and two grants with distinct opportunity IDs. Repeat a slot number after restart to test the epoch boundary. Treat an inactive pilot and a physically measured zero as different mask states. A score from an older generation cannot close a newer opportunity.

### S3.5 Run the cuSense front end and location model on the receiver's estimate · `cusense_frontend`

- **Build.** In `src/ocudu_cuda_isac/sensing/cusense.py` and `src/ocudu_cuda_isac/sensing/models/cusense_cnn.py`, implement the three cuSense stages on observation records. The demonstration input is O3 from S5.2: the receiver's own estimate per DMRS symbol, after frequency interpolation and before time interpolation, which is the stage cuSense reads from Aerial. At the demonstration profile it holds four RX × 612 subcarriers × two DMRS symbols. Stage 1 averages the complex estimates of target-absent calibration records into a background template `H_B[a,k,s]` over antenna, subcarrier and DMRS symbol, using only valid elements. Stage 2 takes the UL slots of one TDD period as a causal window, places each slot at its PRB offset, averages coherently, subtracts the template in the magnitude domain, averages over the DMRS symbols and applies a z-score. Stage 3 is a plain-block 1D CNN from `[B, A, K]` to an `H×W` location grid with a softmax, trained with KL divergence against a Gaussian-smoothed target. Make two documented changes. Fit the template and the normalization statistics on the training split only. Train a presence logit jointly with the grid (binary cross-entropy on every sample, KL on present samples only), so that target-absent episodes are scored. Register O2 on the comb (306 pilot subcarriers per DMRS symbol) as a second input entry, so that the same pipeline can be trained and scored on the observer's estimate. Averaging recent maps and Kalman filtering of the position are an optional stage with its own output. [Villa et al., section 5.2](https://arxiv.org/abs/2512.06493v3)
- **Unit.** At one element, calibration values `1+1j`, `3-1j` and one invalid zero give a template of `2+0j` from two samples. Two window slots holding `1+0j` and `0+1j` average to `0.5+0.5j` with magnitude 0.7071. A template magnitude of 0.5 leaves 0.2071, and training statistics of mean 0.2 and deviation 0.1 map it to 0.071. A slot at PRB offset 2 lands on subcarrier 24. Reject statistics that name a validation or test record. The model returns `[B, H, W]` summing to one per sample for both input widths. KL divergence of a distribution with itself is 0. A uniform prediction over four cells against a one-hot target gives ln 4 = 1.386294. Absent samples give a zero grid-loss gradient. Changing future records or truth fields leaves the current features unchanged.
- **Integrate.** Train on the O3 records that S3.2 published for the training trajectories of the S2.2 episode set. Calibrate the presence threshold on validation negatives with the S3.4 procedure and freeze it. Run batch-one inference in the sensor process on held-out records and join by observation ID and input digest. Score presence on all held-out episodes and position error on the present ones, raw and smoothed. Repeat the training and scoring on O2, and run the S3.4 linear head on the same windows.
- **Accept.** One frozen artifact holds the template, normalizer, weights, threshold, grid geometry and units, each with a hash. Offline and device scores agree within the declared tolerance. `cusense_eval.json` reports presence counts and position error (mean, median, 90th percentile, in metres) with denominators. Grade the stages and the presence decision. Record position error and batch-one latency beside cuSense's published 73 cm mean error and 241 µs live inference in `cusense_reference.json` with `"graded": false`, and list every difference: a simulated scene, 20 MHz against 100 MHz, GB10 against GH200, the inference engine and the latency boundary. The aim is comparable performance in software, judged the way S1.2 judged Table II timing. The published position error belongs to one room and is not a target. At 18.36 MHz the nominal delay resolution is 54.5 ns, about 16 m of bistatic path, so position at room scale comes from structure the model learns across antennas and frequency in the trained scene.

### S6.9 Take receiver evidence from every PHY channel · `channel_sources`

### S6.10 Sense without a UE and with one · `ue_realization`

### S6.11 Train joint sensing and communication objectives · `joint_objectives`

## Where to start when a gate fails

| Observation | First discriminating check |
|---|---|
| CUDA was configured but CPU and GPU appear identical in the log | Check the build cache, CUDA targets, binary identity, actual residency counters and completed decodes on the measured row. |
| CRC passes but the captured estimate is zero | Inspect the active producer. Validate O2 against known pilots, then inspect O3's device producer, event ordering, precision and lifetime. |
| Presence fires on absent scenes | Inspect the physically absent background, held-out split, training-only normalizer, invalid-mask handling and runtime feature allowlist. |
| Radio tails grow under concurrent inference | Hold offered releases fixed. Compare tap-off, copy-only and full sensing. Use completion traces to locate the delay. |
| Apparent network or MIG gain changes with deployment | Compare timestamp uncertainty, matched payload and transport-only controls on M2. Compare per-profile isolated and full-GPU runs on the same station for M3. |
| The page shows a count the scorecard does not | Regenerate `kpi.jsonl` from the archived bundle in replay and diff it against `kpi_parity.json`. The raw events decide. |
| PHY tails grow when the page is open | Check the viewer location and the GPU client list, the aggregator's CPU set and the page-off arm of `gui_impact.json`. |
| A calibrated deadline is missed in the evidence run | Compare the host state with the one recorded in `slo_calibration.json` before changing any value. A recalibration is a new run and a new profile hash. |
| The receiver's estimate and the observer's disagree | Check the producer trace and generation first, then the smoothing stage, scale and FP16 conversion against the flat-channel fixture of S5.2. |
| A new source, split or host changes a sensing result | Compare its observation record with the staged-harness reference on common support before looking at the model. |

For each failed gate retain the fixture digest, command, failing expected/observed value, raw log and smallest subsequent rerun. Update the ticket with its separate unit and integration status.
