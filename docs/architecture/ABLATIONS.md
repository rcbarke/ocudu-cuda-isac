# Ablation axes and the port contract

Every factor that a paper varies is an axis. Every option on an axis is a registry entry with a name, one module and one unit test. A run names one entry per axis. A comparison changes one axis and holds the rest. This page lists the axes, where each entry is built and what each host can supply. The tickets are in the [development plan](../dev/DEVELOPMENT.md).

## A run names its entries

A run configuration carries an `axes` object. The launcher resolves every name against its registry before any allocation and refuses an unknown name. The run manifest stores the resolved entries with the hash of each module.

```json
{
  "schema": "isac-run/v1",
  "axes": {
    "source": "pusch_dmrs",
    "ue": "replayed_cfr",
    "stage": "o3_executed",
    "clutter": "background_magnitude",
    "detector": "frozen_threshold",
    "angle": "none",
    "model": "cusense_cnn",
    "heads": ["presence", "location_grid"],
    "training_domain": "receiver_executed",
    "memory_path": "pinned_host_ring",
    "gpu_sharing": "mps_default",
    "placement": "one_spark",
    "split": "staged_harness",
    "host": "deepsig_ocudu"
  }
}
```

A paired comparison is two such objects that differ in one key. The pair checkers of S5.5, S6.7, S8.2 and S11.4 enforce that.

## Where the code lives

| Directory | Holds | May import |
|---|---|---|
| `src/ocudu_cuda_isac/episodes/` | Grant records, ray-traced episodes, UE realizations, measured and over-the-air captures | Sionna, Sionna RT. Offline only. |
| `src/ocudu_cuda_isac/sensing/` | The sensing core: `sources/`, `features.py` (radar cube), `cusense.py`, `spectral.py`, `angle.py`, `presence.py`, `windows.py`, `models/` | NumPy and PyTorch. No host, no simulator. |
| `src/ocudu_cuda_isac/telemetry/` | The `kpi/v1` aggregator | Standard library. No CUDA context. |
| `src/ocudu_cuda_isac/evaluation/` | Scorecard, study metrics, receiver parity | The record schemas |
| `native/ocudu_adapter/` | DeepSig-OCUDU adapter: `fixtures/`, `replay/`, `receiver/`, `observer/`, `transport/`, `ingress/` (with the ZeroMQ channel broker), `du/` | The locked OCUDU headers |
| `adapters/aerial_framework/`, `adapters/aerial_ocudu/` | One adapter per Aerial host | That host's interfaces and the record schemas |
| `gui/`, `scripts/serve_gui.py` | The live KPI page | Standard library |
| `experiments/` | `demo/`, `splits/`, `conference/` (with `memory/`), `aerial/`, `ota/` | Configuration only |

Three rules keep an entry from leaking into another axis.

1. **The sensing core has no host.** It receives the observation record of S3.2 and returns decision records. `tests/unit/test_core_imports.py` fails if the core imports an adapter, an OCUDU binding or a Sionna package.
2. **A host is an adapter.** An adapter produces the same observation record and accepts the same decision record as every other adapter. Fields that only one host has live under a `host` key and are never read by the core.
3. **Simulation stays offline.** Episodes are generated and stored before a run. No slot loop calls the simulator.

## Add an entry

1. Add the module under the axis's package and register its name.
2. Add a unit test with a hand-checkable vector, as the ticket's Unit field does.
3. Add the name to the table above and to the axis list in the frozen protocol if a paper uses it.
4. Change nothing else. If another module needs a change, the interface is wrong: fix the interface in its own patch first.

## What each host can supply

| | DeepSig-OCUDU staged harness | DeepSig-OCUDU DU at a split | Aerial Framework | Aerial-OCUDU over the air |
|---|---|---|---|---|
| Sources | PUSCH DMRS | PUSCH and PUCCH DMRS, SRS. Downlink sources through S6.9. | PUSCH DMRS | PUSCH DMRS and SRS as E3 streams |
| UE | Replayed CFR, no UE | Replayed CFR, or an OAI softUE on split-8 ZeroMQ | Emulated by test vectors | Pixel 7 |
| Stages | O1, O2, O3 | O1, O2, O3 | The Framework receiver's estimate | Aerial's DMRS estimates at the same stage as O3, fronthaul I/Q |
| Truth | Simulator, offline | Simulator, offline | Test vectors, offline | Independent labels |
| Radio outcome | True CRC against known bytes | True CRC, scheduler events | CRC against test vectors | TB CRC from E3, application goodput with a UE |
| GPU sharing | MPS | MPS, MIG on GB300 | The runtime's own placement | MPS, MIG, time slicing |
| Timing claim | Staged, labeled | Wall clock with DU pacing. None in ZeroMQ lockstep. | Valid on the two-node placement | Live |

A cell a host cannot supply is recorded as a planned cell with its reason. It is not approximated from another host.
