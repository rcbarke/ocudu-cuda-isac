## Native receiver and observation hook

Start from WG1's `docs/phy_cuda_acceleration.md` for the build, accelerator selection and unit/throughput tests. Preserve the native PUSCH demodulation, channel estimation, decode, CRC and available fallback behavior. First reproduce a known upstream transport block with the tap disabled. Next publish a read-only observation while maintaining parity with that decode. Finally inject a known waveform with a replayed channel into a supported receiver boundary and compare GPU results with the matched CPU path. A dummy RU provides timing/load; target echoes and successful UE decoding each require their own evidence. The first CUDA-OCUDU paper measured an earlier WG1 revision and supplies architecture and experiment context. [WG1 acceleration notes](https://gitlab.com/ocudu/work_groups/wg1_hw_accel/cuda_accelerated_ocudu/-/blob/27e84cb3da65205b55dbd56ace6fac93a035331e/docs/phy_cuda_acceleration.md) · [Pennybacker et al.](https://arxiv.org/abs/2608.04338v1)

For frequency-domain grid observations, inspect `include/ocudu/phy/upper/phy_tap/phy_tap.h`, `lib/phy/upper/uplink_processor_impl.cpp` and `lib/phy/upper/upper_phy_factories.cpp` together. At this pin the implementation submits PUSCH first, stages an owned grid snapshot when a tap is configured, then invokes `handle_ul_symbol`. The callback runs in a time-sensitive context. Preserve this order. The generic tap supplies grid and allocation metadata. An estimate produced inside the PUSCH estimator needs a separate publication point, tagged with the estimator stage and its completion event. Retain or copy the intended view until the consumer releases it. Do not save a borrowed grid pointer or infer the validity of a device buffer from its host address. [UL implementation at the pin](https://gitlab.com/ocudu/work_groups/wg1_hw_accel/cuda_accelerated_ocudu/-/blob/27e84cb3da65205b55dbd56ace6fac93a035331e/lib/phy/upper/uplink_processor_impl.cpp)

The project owns the bounded queue, read-only descriptors, sequence/slot/UE identity, readiness and release rules, mask and tensor layout, telemetry, and evidence that export neither changes decode nor blocks the PHY. A receiver stage named `LS` must carry the actual LS result or a documented recomputation from the received pilots; filtered/interpolated estimates require their own tag and physical coordinates. Preserve the source's timestamp and symbol/grant identity across all deployments.

## Offline scene and PHY generation

1. Choose UE transmitter and gNB receiver positions, arrays and axes, carrier, scene materials, target geometry/trajectory, and actual OFDM symbol times. Specify a bistatic UE–target–gNB geometry when simulating uplink sensing. Keep the direct UE–gNB path and ordinary multipath. A co-located monostatic tutorial uses different range/Doppler geometry. [RCS tutorial](https://nvlabs.github.io/sionna/rt/tutorials/RCS.html)
2. Compute background paths with `PathSolver` using the selected materials and propagation flags. Diffuse reflections require enabling the mechanism and specifying a material with nonzero scattering. Reuse `RCSSolver` with `ConstantRCSSensingTarget` for a controlled reflector or `TR38901SensingTarget` for a supported standard model. Target-path legs support LOS, specular reflection and refraction. The background solver supports additional mechanisms such as diffuse reflection and diffraction. Model and declare any additional target micro-motion separately. [RCS model and limits](https://nvlabs.github.io/sionna/v2.2.0/rt/api/rcs.html) · [scattering tutorial](https://nvlabs.github.io/sionna/rt/tutorials/Scattering.html)
3. Combine compatible same-scene path sets with `background_paths.concat(sensing_paths)` and generate a complex MIMO channel using `Paths.cfr`. Set subcarrier offsets, sampling frequency and time origin explicitly. For absolute-delay validation, choose `normalize_delays=False` and preserve physical amplitudes with `normalize=False`. `cfr` uses a uniform temporal grid. For unequal CP intervals or larger motions, evaluate/resample onto actual symbol times with a documented error check and use short, continuous-phase geometry intervals. Count motion-induced phase evolution once. Remove the target from the absent scene and recompute affected background paths because target meshes can shadow paths. [Paths API](https://nvlabs.github.io/sionna/rt/api/paths.html) · [mobility tutorial](https://nvlabs.github.io/sionna/rt/tutorials/Mobility.html)
4. Reuse NR PUSCH/DMRS generation and ISAC transforms for offline checks. Adapt carrier/grid origin, BWP/PRB and guard/DC indices, port/layer order, OFDM symbol timing, DMRS mask, constellation scaling and dtype to the exact receiver grant. In a diagonal-OFDM model form `Y[k,l] = H[k,l] X[k,l] + W[k,l]`, summing over transmit ports. Record this model's within-CP/small-ICI assumptions; use a time-domain channel when deliberately studying their violation. Store the scene, license, exact source revisions, solver flags and RNG seeds, clocks, transmit bits/grants, replay bytes/checksums and labels. Stock scenes, notebooks and APIs make the traces reproducible; the project must generate the slot-aligned episodes. Only received samples, reference symbols and causal receiver metadata enter online inference. [Sionna PHY NR](https://nvlabs.github.io/sionna/phy/api/nr/index.html) · [Sionna PHY ISAC](https://nvlabs.github.io/sionna/phy/api/isac/index.html)

## Attribution and version discipline

Keep upstream source, copyright notices and licensing with each checkout. WG1 includes component-specific notices in `LICENSES/` and `REUSE.toml`. Both pinned Sionna projects provide their own licenses. Preserve attribution for imported scenes, including third-party assets. NVIDIA identifies `aerial-sample-apps/dapps` as Apache-2.0. This does not grant rights to a third-party model/checkpoint. Save origin, revision, license and hash for every downloaded scene, model or dataset before using it in a published experiment.
